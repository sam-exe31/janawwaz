# Phase 2 IVR Intake Channel Architecture

## 1. Overview
The Janawwaz Civic Issue Platform supports multimodal intake. While Phase 1 focuses on Web & Mobile Photo submissions, Phase 2 enables direct voice telephone calls via Interactive Voice Response (IVR) systems for citizens without smartphones or internet access.

## 2. Architecture
```
[ Citizen Phone Call ]
         │
         ▼
[ Twilio / Exotel / Local Telecom Gateway ]
         │ (Inbound Webhook)
         ▼
[ Janawwaz IVR Controller: POST /api/v1/intake/ivr/incoming ]
         │
         ├─► Audio Recording & Storage (S3 / Local Vault)
         ├─► Google Gemini Multimodal / Speech-to-Text (`TRANSCRIBE`)
         ├─► Category Extraction & Named Entity Recognition (Location)
         └─► State Machine (`SUBMITTED -> SCREENING -> OPEN`)
```

## 3. Data Schema
Requests created via IVR populate:
- `source`: `'IVR'`
- `input_type`: `'IVR'` or `'VOICE'`
- `voice_url`: Presigned URL to MP3 audio recording
- `caller_phone_verified`: `TRUE` (Caller ID validated via telecom CLI)
- `description`: Automated Marathi / Hindi / English transcript generated by Gemini
- `location`: Inferred from spoken address or nearest cell tower triangulation

## 4. Security & Spoofing Prevention
1. Telecom Carrier Handshake: Validated via HMAC-SHA256 signature on webhook payloads.
2. Caller Rate Limiting: Max 3 calls per phone number per day.
3. Transcription Verification: Admin review queue for ambiguous voice transcriptions.
